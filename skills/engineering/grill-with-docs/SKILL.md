Call the Skill tool twice, for "grilling" and "domain-modeling".

For software design interviews, load the project's canonical documentation standard/manifest when available. Record **all settled implementation-relevant decisions** in the canonical decision ledger or approved requirements artifact, not only glossary terms and ADR-worthy choices. Link decisions to affected requirements/rules/scenarios; keep unapproved answers proposed, verify that files were persisted and reuse existing documentation destinations. The glossary remains vocabulary-only and ADRs remain for significant trade-offs.
